New `:feature:auth` module ships:

- **`data/AuthApi`** — Retrofit interface for `POST /api/v1/auth/login` + `POST /api/v1/auth/logout`.

- **`di/AuthModule`** — Hilt `@Module` discovered automatically by `:app`'s KSP processor.

## Critical infrastructure context

Active workarounds — **read these before working on Android PRs**:

- **`api` scope discipline for `:core:*` and `:feature:*` modules.** When a module's public API returns a type from a transitive dep (e.g., `:core:network` returning `Retrofit`, `:core:database` returning `RoomDatabase`), the underlying lib MUST be `api(libs.x.y)`, not `implementation(libs.x.y)`. Without `api`, downstream modules' compile classpath can't resolve the type and Hilt KSP fails with `error.NonExistentClass`. Already applied: `:core:network` (okhttp / retrofit / json), `:core:database` (room-runtime + room-ktx).

- **Prettier vs. Room schema JSON.** `apps/android/core/database/schemas/<db-class>/<version>.json` is auto-generated by the Room KSP processor at compile time. Prettier's default formatter wants to rewrite the trailing newline + indent, which would corrupt Room's identity-hash check at runtime. **`.prettierignore` excludes `apps/android/core/database/schemas/`** — keep this rule. Future schema bumps create new files (`2.json`, `3.json`) in the same directory; the ignore line covers them all.

- **`@HiltViewModel` requires KSP in the same module.** For `@HiltViewModel`-annotated classes, the Hilt processor must run in the same module that declares them — classpath scanning from `:app`'s processor is NOT sufficient. Affected modules: `:feature:auth` (LoginViewModel) and `:feature:home` (HomeViewModel) both apply `alias(libs.plugins.ksp)` + `ksp(libs.hilt.compiler)`. Without this, `assembleDebug` fails with `MissingBinding`.

- **`collectAsStateWithLifecycle` ships from `lifecycle-runtime-compose`.** Not `lifecycle-viewmodel-compose`. The two artifacts are separate; importing only `viewmodel-compose` causes `Unresolved reference: collectAsStateWithLifecycle` at compile time. Both libs are now in `libs.versions.toml` with a comment tracking the gotcha.

- **KDoc `*/` inside backticks.** Kotlin's KDoc parser doesn't escape `*/` even when it's inside backticked code (e.g., `` `*/api/v1/auth/*` ``). The `*/` closes the comment prematurely, causing `Unclosed comment` errors. Workaround: paraphrase the content (e.g., "the `...` endpoints"). Tracked in `AuthApi.kt` + `AuthDto.kt`.

- **PR creation via REST API + GitHub PAT.** The git-manager proxy returns 403 on `git push` for some branch names; the protocol §4 fallback (PAT-only push via mktemp `GIT_ASKPASS_SCRIPT` + `HOME=/tmp/empty-home` + `GIT_CONFIG_NOSYSTEM=1`) was used for every PR this session and works reliably. PR creation also bypassed `git_pr` and used `curl https://api.github.com/repos/.../pulls` directly because of similar proxy issues. Both flows are documented in the protocol doc; reuse them.

## Operational notes for next session

- **Local build cadence.** Each P3-0X PR adds ~200–400 KB of compose-compiler output to the gradle build cache. After 5 PRs the cache is ~600 MB — the next session should expect `./gradlew :app:assembleDevDebug --no-daemon` to take ~2–3 min on a cold cache and ~30–60 s when only one feature module changes. Don't use `--daemon` (CI matches no-daemon and cache invalidation is more predictable).
- **APK size baseline is now 11 MB** (was 8.6 MB at end of P3-02). Of the 2.4 MB delta: ~800 KB OkHttp+Retrofit (P3-05), ~500 KB DataStore+coroutines (P3-03a), ~100 KB Room (P3-04), ~1 MB Compose-in-feature (P3-03b debug only — R8 collapses in release), 0 nav-compose (P3-08).
- **Sideload verification is high-value.** Every Android PR ships an `app-staging-debug.apk` artifact via the CI's `build (apps/android assembleDevDebug + assembleStagingDebug)` job. Founder can sideload from the GitHub PR's "Artifacts" section and exercise the login → home flow end-to-end against the staging VPS endpoint without needing a local Android Studio install.
- **Quota check at session start.** This session continuation merged 5 Tier 1 PRs (#193–#197) plus the prior rotation's #190–#192 — total 8 PRs in the day. The founder corrected my quota math at one point (claimed 85% based on web display vs. actual 37% daily / 18% weekly). Always check the actual Devin webapp quota indicator before stopping early; don't trust internal heuristics.
- **The 4 CI jobs always run on Android PRs even though only one matters.** `lint + format:check` (whole repo Prettier), `build (web + backend)`, `test (--if-present)` (mostly noop because backend tests don't have a `--if-present` script for paths), and `build (apps/android assembleDevDebug + assembleStagingDebug)`. All four must be green for merge eligibility.
