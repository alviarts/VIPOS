## 5. Outstanding follow-ups (in execution priority order)

### 5.1 — HTTPS / domain cutover (~1-2h, needs founder input)

**Why now:** Until HTTPS is live, several user-facing limits hit:

- Service Worker / PWA: cannot register on non-localhost HTTP → no offline mode
- `getUserMedia` (camera for barcode scan): blocked outside secure context
- "Not secure" badge in browser address bar — visible during merchant demo
- Mobile native app (Phase 3): App Transport Security (iOS) / Network Security Config (Android) reject HTTP API by default

**Founder decision needed first:**

- What domain? Options: `app.vipos.id` / `vipos.app` / sub of an existing domain. Founder previously said "belum ada domain". Once decided, see acquisition options: Niagahoster / Domainesia / Cloudflare Registrar.
- DNS provider access (founder needs to grant or proxy via Cloudflare).

**Devin execution plan once founder decides:**

1. SSH VPS, install certbot via apt (`certbot` + `python3-certbot-nginx`)
2. Update nginx config: add `server_name <domain>` + redirect HTTP → HTTPS, listen 443 ssl, add `add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;`
3. Run `certbot --nginx -d <domain>` (interactive: email + ToS), verify auto-renewal cron in `/etc/cron.d/certbot`
4. Update backend `.env`: `CORS_ALLOWLIST=https://<domain>` (or comma-sep list); `pm2 restart vipos-backend --update-env`
5. Rebuild frontend with new domain reference if any (nothing currently bakes the URL — relative paths)
6. Update DEPLOYMENT.md ascii diagram + mention domain in deploy-checklist
7. Closes F5 (signup slug placeholder) — update `apps/web/src/pages/SignupPage.jsx` placeholder to match
8. PR title: `feat(ops): HTTPS cutover via Let's Encrypt + domain <domain>`

### 5.2 — `vipos_app` Postgres password rotation (~10 min, low risk)

**Why:** Default `apppass` is a weak placeholder, even though loopback-only. Rotate before sharing this VPS with anyone.

**Devin execution plan:**

1. SSH VPS, generate password: `pwd=$(openssl rand -base64 32 | tr -d '=' | head -c 40)`
2. As superuser: `ALTER USER vipos_app WITH PASSWORD '<new>';`
3. Update `apps/backend/.env`: `DATABASE_URL=postgresql://vipos_app:<new>@127.0.0.1:5432/vipos`
4. `pm2 restart vipos-backend --update-env`
5. Verify `/api/health` 200 + `db.ok=true`
6. Save the new password somewhere persistent (similar to `/root/.vipos-pg-pwd` for the superuser)
7. Doc-only PR if any docs reference `apppass` literal (none currently in main, but check `.env.example`)

### 5.3 — Redis + BullMQ + S3 backup wiring (optional, 1-3h depending on scope)

**Why:** None are blockers. BullMQ enables async background jobs (e.g., scheduled reports); S3 enables off-VPS DB backup (currently nothing); Redis enables session cache + BullMQ broker. All are architecture upgrades for Phase 2+ scaling.

**Sub-tasks (each its own PR):**

- Install Redis 7 via apt, set `REDIS_URL=redis://127.0.0.1:6379` in backend `.env`, restart pm2, verify `/api/health` `redis.enabled=true`. Bench impact on health latency.
- BullMQ worker registration (already in code via P2-04?). Verify by triggering a known background job (check `apps/backend/src/jobs/` if exists).
- S3 backup cron: provision AWS IAM scoped user (RW to one bucket), set `S3_BACKUP_*` env vars, install + schedule a `pg_dump | gzip | aws s3 cp` cron at 03:00 WIB. Document restore drill in deploy-checklist §3.

### 5.4 — Sentry source-map upload (~30 min)

**Why:** Currently Sentry shows minified stack traces. With sourcemaps uploaded per release, traces become readable. Defer until ≥1 alpha merchant produces real errors so the value is concrete.

**Devin execution plan:**

1. Install `@sentry/cli` on VPS (or in CI later)
2. Generate source maps (already done by Vite — `dist/assets/*.js.map`). Optionally exclude maps from being publicly served via nginx `location ~* \.map$ { return 404; }`
3. After each `npm run build`, run: `sentry-cli releases files vipos-web@<sha> upload-sourcemaps dist/assets/ --rewrite --strip-prefix /var/www/vipos/apps/web`
4. Bake into deploy-checklist §2.6.2
